**Goal:** Read and show the File Options metadata fm 0.8.0-beta.0 newly reports, bring the step-display fixture up to that build, teach the two new calculated-name steps to the analyses that care, resolve the three new keys that name solution objects, report the references fm says are already dead, and stop the read-only guard from refusing ops fm declares read-only.

**Spec:** `docs/superpowers/specs/2026-09-21-fm-0.8.0-support-design.md`

## Global Constraints

- **Read-only, always.** Only `read:*`, `evaluate:calculation` and `validate:calculation` may ever be sent. `server/read.mjs` enforces it through `assertReadOnly`; never weaken that guard. The reference solution is read and never written.
- **`ui/` is browser-safe.** No `document`, no `node:` imports, no `server/` imports in any file under `ui/`. Pure functions to strings and plain objects.
- **Every fm key through `ui/access.js`** (`get` / `path`), never a bare property read — fm respells keys between builds.
- **Every model string through `esc()`** before it reaches HTML.
- **Test command quoting matters:** `node --test 'tests/*.test.mjs'`. The bare directory form fails on Node 22.19. Full suite: `npm test`.
- **The toolkit is upstream.** Anything about fm's wire format, step rendering or known gaps belongs in `fm-adt-toolkit`, not here. This plan changes no toolkit code.
- **Analyses are memoised** through `ui/analysis/memo.js`, which keys on what a re-read *replaces*. Any new model slot an analysis reads must be added to `fingerprint()` or the analysis goes stale on re-read.
- **fm's own words for fm's own settings.** Labels follow FileMaker's File Options dialog, not fm's key spelling.

- [ ] **Step 4: Classify by verb**

Replace the classification in `src/read-only.ts`, keeping the existing exports so nothing downstream breaks:

```ts
/** The verbs fm's own help declares do not write. `read` and `search` are the two
 *  that answer questions: a search's help is explicit -- "NOTHING HERE WRITES. No
 *  scanner opens a catalog for writing, nothing joins the commit lifecycle, no
 *  result reports `dry-run`, and `--dry-run` does not change what this op does."
 *  `evaluate` and `validate` are the calculation verbs, whose help says a file's
 *  bytes are identical after evaluating -- including a formula that assigns a
 *  global.
 *
 *  Classified by VERB rather than by name prefix, and that is the point. The
 *  previous rule was `name.startsWith('read:')`, which encoded "a read-only op is
 *  spelled read:" -- true until fm 0.8.0 added nine `search:*` ops, every one of
 *  which this guard then refused. A tool built on this guard silently lost a
 *  capability the CLI had gained. Verb is stable, there are eight of them, and fm
 *  names every one of its 102 ops `verb:noun`. */
export const READ_ONLY_VERBS: ReadonlySet<string> = new Set(['read', 'search', 'evaluate', 'validate']);

/** The verbs that change a file. Kept explicitly, and not as "everything else",
 *  so that a verb fm adds later is in NEITHER set and fails the classification
 *  test rather than defaulting into one of them. */
export const WRITE_VERBS: ReadonlySet<string> = new Set(['create', 'delete', 'duplicate', 'update']);

/** Kept for callers that referenced it; the verb sets are the classification now. */
export const READ_ONLY_CALCULATION_OPS = new Set(['evaluate:calculation', 'validate:calculation']);

export function isReadOnlyOp(op: unknown): boolean {
  const name = (op as { op?: unknown })?.op;
  if (typeof name !== 'string') return false;
  const at = name.indexOf(':');
  if (at <= 0) return false;
  return READ_ONLY_VERBS.has(name.slice(0, at));
}
```

Leave `assertReadOnly` as it is — it calls `isReadOnlyOp` — but widen its message:

```ts
      throw new Error(`op ${JSON.stringify((op as { op?: unknown })?.op)} is not read-only; only ${[...READ_ONLY_VERBS].sort().map((v) => `${v}:*`).join(', ')} may be sent`);
```

### Task 0, Part B: the register must stop claiming fm tokenises variables

Found during Task 1's first dispatch, which could not close `catalog-calculation-tokens` honestly.
The `calculation-tokens` entry has ONE coarse attribute — "tokenised references of a formula (fields,
occurrences, variables, functions, scripts)" — now marked `reported: true`. Its own `knownFrom` prose
contradicts that flag: "PARTIAL against the SaXML chunk list this row is drawn from … **It reports NO
token for a variable, a built-in function, a plug-in function or a script.**"

The prose is right and the flag is what machines read. Every inventory row in the inspector mapped to
this gap id is about `$$` **variables**, which fm does not tokenise — so with the flag as it stands,
the inspector would have to call those rows `covered` and thereby assert that fm names the variables
a formula reads. `ui/analysis/globals.js` exists because it does not.

- [ ] **Step 5b: Let an attribute expect a scalar, not only an array**

`isReported` supports `expect: { contains }` only for an array of scalars — it exists for the 28
layout rows that all read `flags.set`. Check it:

```bash
cd ../fm-adt-toolkit && sed -n '81,90p' src/gaps/check.ts
```

`valuesAt(instance, 'references[].kind')` yields one **string** per element (`'field'`), so an
array-only test can never match it — and would stay false even after fm starts emitting a variable
token, which is a broken ratchet rather than a recorded gap. Widen the predicate to accept either
shape, in `src/gaps/check.ts`:

```ts
/** Whether fm reports this attribute on this instance: the fmKey is present, and -- when
 *  the row carries an `expect` -- the value says what the row claims. Several rows share
 *  one key (28 layout option rows all read `flags.set`), so presence alone would report
 *  every one of them the moment any single flag is set.
 *
 *  The value may satisfy `contains` two ways: BE the expected scalar, or be an array holding
 *  it. The array form is what `flags.set` needs. The scalar form is what a row keyed on an
 *  element field needs -- `references[].kind` yields one string per element, so an array-only
 *  test could never match it, and a row written that way would read as a permanent gap even
 *  after fm began reporting it. A gap that cannot close is worse than no row. */
function isReported(instance: unknown, a: Attribute): boolean {
  if (!a.fmKey || !hasKey(instance, a.fmKey)) return false;
  if (!a.expect) return true;
  return valuesAt(instance, a.fmKey)
    .some((v) => v === a.expect!.contains || (Array.isArray(v) && v.some((x) => x === a.expect!.contains)));
}
```

### Task 2b: Do not tokenise fm's opaque round-trip blobs

Found by measuring after Task 2's re-record, not by any review. **A single `references()` call on the
re-recorded fixture takes 105 seconds.** Before the re-record the whole suite ran in 1.5s. This is not
a test-speed problem: `ui/` computes `references()` live for the Analysis, Explorer and Graph tabs, so
the page would appear hung, and Task 8's browser pass would time out.

The cause, measured in three steps:

1. The bulk of the new string data is the key `data` — 176 strings, 1,202,348 chars, up to 52,340
   each — living at `printOptions.preserved[].data` and `pageSetup.preserved[].data`, both new in
   0.8.0. They are **hex-encoded plists**: `3C3F786D6C…` is `<?xml version=…<!DOCTYPE plist`.
2. `refs.js` tokenises every string it walks, and `FIELD_RE` is `NAME_CHARS::NAME_CHARS` where every
   hex digit is a valid name character. With no `::` and no delimiter anywhere in 52KB, every start
   position rescans forward maximally — O(n²).
3. Timed directly: hex at 2k/4k/8k/16k chars costs 29/56/184/788 ms, and the *same* 16k length
   carrying delimiters costs 9 ms. That 88× gap is why the theme `css` strings (521KB, present since
   0.7.0) never caused this and the hex blobs do — CSS has braces, colons and spaces that break the
   runs.

The step renderer is *not* affected, which was worth confirming: the catalog marks `printOptions`,
`pageSetup`, `importOptions` and `exportOptions` as `ignored`, and a Print step renders
`Print [ With dialog: On ]` with no hex on the line.

 *  `icon` reports `hasImage` and no bytes -- so the block can be rendered as it
 *  arrived without leaking a credential. */
function optionValue(target, label, at, value) {
  if (value === undefined || value === null) return '<span class="muted">not reported</span>';
  if (typeof value === 'boolean') return value ? 'yes' : 'no';
  if (at === 'minimumVersion') {
    const version = get(value, 'version');
    const raw = get(value, 'value');
    if (version === undefined || version === null) return esc(String(raw ?? ''));
    return `<span title="${esc(`fm reports ${raw}`)}">${esc(version)}</span>`;
  }
  if (at === 'layout') {
    const name = get(value, 'name');
    const id = get(value, 'id');
    if (name === undefined || name === null) return '<span class="muted">none</span>';
    return id === undefined || id === null
      ? esc(String(name))
      : link(`layouts/${selectionKey(target, id)}`, String(name));
  }
  // The icon is three facts on one line: what kind, how it is scaled, and
  // whether a picture came with it. fm sends no image bytes.
  if (at === 'icon') {
    const parts = [get(value, 'type'), get(value, 'scale')].filter((p) => p !== undefined && p !== null);
    if (get(value, 'hasImage') === true) parts.push('has an image');
    return parts.length ? esc(parts.join(', ')) : '<span class="muted">not reported</span>';
  }
  return esc(String(value));
}

/** File Options, one block per file. The labels are the Solution tab's, so the
 *  report and the page name the same setting the same way; the values are read
 *  straight off the block because fm sends no password and no image bytes. */
function fileOptions(solution) {
  const parts = [];
  for (const file of filesOf(solution)) {
    const slot = get(file, 'fileOptions') ?? {};
    const error = get(slot, 'error');
    const block = get(slot, 'block');
    parts.push(`### ${mdCell(nameOf(file))}\n`);
    if (error) {
      parts.push(`\`${mdCell(get(error, 'code'))}\`: ${mdCell(get(error, 'message'))}\n`);
      continue;
    }
    if (!block) {
      parts.push('Not read.\n');
      continue;
    }
    const yesNo = (v) => (typeof v === 'boolean' ? (v ? 'yes' : 'no') : v);
    const rows = [
      ['Startup layout', get(block, 'switchToLayout') ? (path(block, 'layout.name') ?? '(none)') : 'not on open'],
      ['Minimum FileMaker version', path(block, 'minimumVersion.version') ?? ''],
      ['Log in as', path(block, 'login.mode') ?? ''],
      ['Allow stored credentials', yesNo(get(block, 'allowStoredCredentials'))],
      ['Require authorization', get(block, 'requireAuthorization') ?? ''],
      ['Hide all toolbars', yesNo(get(block, 'hideToolbars'))],
      ['Date, time and number formats', get(block, 'dataEntry') ?? ''],
      ['Thumbnail storage', get(block, 'thumbnailStorage') ?? ''],
    ].map(([k, v]) => [k, v === undefined || v === null ? '' : v]);
    parts.push(mdTable(['Setting', 'Value'], rows, { align: 'll' }));
    const triggers = (get(block, 'triggers') ?? []).map((t) => [get(t, 'event'), get(t, 'script')]);
    parts.push(`\n**Script triggers**\n\n${mdTable(['Event', 'Script'], triggers, { align: 'll' })}`);
  }
  return parts.join('\n');
}

/** Every enabled `Set Variable by Name` step, whose variable name is a formula.
 *  Not a `$$` row: the name is calculation text, and inventing a global called
 *  `"$$" & $prefix` would be a false positive. It is listed so the answer can
 *  say where it is incomplete -- a global written only by one of these steps is
 *  in no row above, and this is the only record that it exists.
 *
 *  Memoised like every other analysis here. */
export const calculatedSetSites = (solution) => memoise(solution, computeCalculatedSetSites);

function computeCalculatedSetSites(solution) {
  const out = [];
  for (const file of filesOf(solution)) {
    const target = get(file, 'target');
    for (const detail of detailsOf(file)) {
      const body = get(detail, 'body') ?? [];
      body.forEach((step, index) => {
        if (get(step, 'disabled') === true || get(step, 'step') !== SET_VARIABLE_BY_NAME) return;
        out.push({
          target,
          script: { id: get(detail, 'id'), name: get(detail, 'name') },
          step: { index, line: index + 1, step: SET_VARIABLE_BY_NAME },
          name: get(step, 'name'),
        });
      });
    }
  }
  Object.freeze(out);
  return out;
}

The spec's error-handling requirement (`unknown_catalog` renders and leaves the page intact) is Task 4 Step 1's fourth test.

**What the intake audit added, and why it was not in the first draft.** The first pass read only the surface diff's additions. Auditing the whole intake — removals, register regressions, the catalog diff, and the *semantics* of the new keys rather than their names — found three things: the guard refuses nine ops fm declares non-writing (Task 0), three new keys name objects `refs.js` skips (Task 5b), and the `*Key` family is fm reporting a dead reference rather than a redundant id (Task 5c). It also confirmed nothing was removed anywhere, so no task needs to defend against a key that vanished.

**Ordering note on Task 0.** It is first because it is the only task that changes what ops this tool may ever send, and it is the only one that touches another repo and pushes a tag. Nothing downstream depends on its output, so it could move — but a reviewer should see it before the inspector work, because the question it answers ("which of fm's 102 ops may we send?") frames everything else.

**Two things the spec did not anticipate, added here.** The memo fingerprint (Task 3 Steps 9–12): `refs.js` reading the block means a File Options re-read must invalidate the analyses, and `fingerprint()` did not watch the slot. And the second re-record (Task 3 Step 17): `replay-api.mjs` throws on an unrecorded op, so the op and the recording must land in one commit. Neither changes the design; both would have blocked an executor.

**Type consistency.** `file.fileOptions` is `{ block, error, ops, readAt }` in Tasks 3–6 without variation. `fileOptionsOps()` returns an array in Task 3 and is consumed as one in `ui/discovery.js`. `from.kind === 'fileOptions'` and `from.id === 'fileOptions'` agree between Task 5's tests and its implementation. `calculatedSetSites` has one shape, asserted in Task 7 Step 2 and built in Step 5. `SET_VARIABLE_BY_NAME` and `REPLACE_BY_NAME` are exported once, in `refs.js`, and imported by name in `globals.js` and `unreferenced.js`.

**One deliberate gap.** Task 2 Step 6 and Task 2 Step 8 pin numbers this plan cannot know, because they are measurements of a recording that does not exist yet. Both steps say how to obtain them, and Step 5 sets the gate (`stepsWithGaps < 45`) that decides whether the measurement is trustworthy at all. That is the opposite of a placeholder: the number is refused until it is measured.
