# Inventory to register

One row per gap id from `docs/saxml-inventory.md`'s "Gap ids introduced" section (13 today). "Register entries and attributes" names `entry.id` / `attribute.name` pairs from `fm-adt-toolkit/gaps/register.json`, each an attribute with `reported: false` and no `wontfix` — a real gap by the register's own accounting. Most gap ids map to many register attributes; the list here is a representative sample, not the full set, except where the notes column says otherwise. Built by keyword search over a dump of every `reported: false, !wontfix` attribute in the register, then hand-matched to each gap id's description in the inventory.

Two gap ids have no eligible register pair and are marked `OPEN ITEM` instead: `catalog-calculation-tokens`, because fm has no key for tokenised calculations at all (there is nothing resembling a gap entry to point to, only calculation-text attributes that already report), and `catalog-layout-options`, because the register's `layout` entry already marks both attributes the inventory names (`layout option: save record changes automatically`, `layout option: enable quick find`) as `reported: true` via `flags.set` — the register and the frozen inventory disagree, and this task's controller ruling permits editing only one unrelated attribute by hand, so the disagreement is recorded here rather than resolved by an unauthorized register edit. `tests/inventory-register.test.mjs` tolerates exactly these two documented exceptions and no others.
